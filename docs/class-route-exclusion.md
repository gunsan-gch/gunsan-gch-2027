# 수업 사이트 이동 세션 제외 — 분석 설정 안내

수업 시간에 학생들이 **입학안내 → 픽셀 투어 → 경영실습실 → 수업 사이트** 순서로 들어오면
그 방문(GA 세션)에 `class_route_complete` 이벤트가 한 번 남습니다.
이 이벤트가 있는 세션을 빼고 보는 것이 **'수업 사이트 이동 세션 제외'** 집계입니다.

> **코드만으로는 아무것도 빠지지 않습니다.** 사이트는 표시만 하고 GA 원본은 그대로 쌓입니다.
> GA4 기본 보고서(보고서 탭)와 Windsor AI 숫자는 **배포 후에도 전과 똑같이 전체 집계**입니다.
> 빼고 보려면 아래 2번처럼 GA4 **탐색**에서 세그먼트를 직접 만들어야 합니다.

## 1. 사이트가 보내는 이벤트

| 이벤트 | 언제 | 매개변수 |
|---|---|---|
| `class_route_complete` | 같은 방문에서 입학안내 → 투어 → 경영실습실 설명을 거친 뒤 **수업 사이트 링크를 처음 누를 때 한 번** | `room_name`(경영실습실), `link_url`(수업 사이트 주소), `route_steps`(`home>tour>room>link`), `route_minutes`(입학안내 첫 화면부터 클릭까지 분, 정수) |
| `tour_room_link_click` | 투어 공간 설명의 바로가기 링크를 누를 때마다 (경로와 상관없이) | `room_name`, `link_url`, `route_status` — `class_route`(이번 방문의 첫 수업 경로 클릭) · `class_route_repeat`(같은 방문에서 다시 누름) · `none`(수업 경로가 아님) |

- 두 이벤트 모두 `page_location`은 투어 주소(`…/gunsan-gch-2027/tour/`)입니다.
- 경영실습실 설명만 열고 링크를 누르지 않은 방문, 투어로 바로 들어온 방문, 입학안내만 본 방문에는 `class_route_complete`가 생기지 않습니다.
- 수업 사이트(`/word-practice/`)에는 GA가 없습니다. 이벤트는 링크를 누른 투어 화면에서 보내고, 링크는 새 탭으로 열려 투어 화면이 남아 있으므로 이동 때문에 빠지지 않습니다. GA4 태그는 탭을 숨기거나 떠날 때도 남은 이벤트를 보내는 방식(sendBeacon)을 기본으로 씁니다.

### 같은 방문인지 판별하는 방법 (`assets/js/class-route.js`)

- 단계는 순서대로만 기록됩니다: 입학안내 첫 화면(`home`) → 투어(`tour`) → 링크가 있는 공간 설명(`room`). 앞 단계 없이 들어온 단계는 기록하지 않습니다.
- **같은 방문 = 같은 GA 세션 번호**입니다. 각 화면에서 `gtag('get', 'G-0RCC2LMBNY', 'session_id')`로 GA가 정한 세션 번호를 받아 비교합니다. 세션 번호를 아직 못 받았으면 GA 기본 세션 시간과 같은 '마지막 기록 후 30분 이내'로 판단합니다.
- 기록은 **localStorage**에 둡니다. 투어나 수업 사이트를 새 탭으로 열어도 같은 주소(`gunsan-gch.github.io`)라 이어서 읽을 수 있습니다. (sessionStorage는 새 탭마다 따로라 쓰지 않았습니다.)
- localStorage는 브라우저를 닫아도 남으므로, 읽을 때마다 **세션 번호가 다르거나 30분 넘게 기록이 없거나 하루가 지났으면 바로 지웁니다.** 그래서 나중에 다시 온 방문은 수업 경로로 분류되지 않습니다.
- 한 방문에서 `class_route_complete`는 한 번만 보냅니다 (여러 탭·반복 클릭 포함). 다른 날 다시 수업 경로를 밟으면 그 새 방문에 다시 한 번 남습니다. 사람(사용자) 단위로 영구 표시하지 않습니다.
- 저장 내용: 단계별 시각, 공간 이름, GA 세션 번호, 보냄 여부. 개인정보는 없습니다.
- 알려 둘 한계: 링크를 오른쪽 클릭 메뉴의 '새 탭에서 열기'로 열면 브라우저가 클릭을 알려 주지 않아 표시되지 않습니다 (일반 클릭·Ctrl+클릭·휠 클릭은 됨). 광고 차단 등으로 GA가 막힌 브라우저는 처음부터 GA에 기록되지 않습니다.

## 2. GA4에서 '수업 사이트 이동 세션 제외' 집계 만들기

### 먼저 한 번만 (관리)

1. **데이터 보관 기간:** 관리 → 데이터 수집 및 수정 → 데이터 보관 → 이벤트 데이터 보관을 **14개월**로. 탐색은 이 기간 안의 데이터만 볼 수 있습니다. (늘려도 이미 지난 데이터는 되살아나지 않습니다.)
2. **(선택) 맞춤 측정기준:** 관리 → 데이터 표시 → 맞춤 정의 → 맞춤 측정기준 만들기, 범위 **이벤트**로 `route_status`, `link_url`을 등록하면 탐색에서 클릭 구분을 볼 수 있습니다. 세션 제외 자체에는 필요 없습니다. 등록한 날부터 집계됩니다.
3. `class_route_complete`를 **주요 이벤트(전환)로 표시하지 마세요.** 홍보 성과가 아니라 구분용 표시입니다.
4. **데이터 필터·내부 트래픽 규칙은 쓰지 마세요.** 데이터 필터는 이벤트를 영구히 버려 원본이 남지 않고, 내부 트래픽(IP) 규칙은 학교 PC 접속 전체를 빼게 됩니다.

### 탐색 만들기

1. **탐색 → 빈 보고서(자유 형식)**, 이름 예: `홍보 분석 · 수업 사이트 이동 세션 비교`.
2. 왼쪽 변수 패널의 **세그먼트 +** → **세션 세그먼트**로 두 개(필요하면 세 개)를 만듭니다.
   - **전체 세션(비교용)** — 포함 조건: `이벤트 이름` · `정규식과 일치` · `.+`
   - **수업 사이트 이동 세션 제외** — 포함 조건은 위와 같게 두고, **제외할 그룹 추가** → *일시적으로 제외*(다음 조건을 충족하는 세션 제외) → `이벤트 이름` · `정확히 일치` · `class_route_complete`
   - (확인용) **수업 사이트 이동 세션만** — 포함 조건: `이벤트 이름` · `정확히 일치` · `class_route_complete`
   - 세션 세그먼트로 빼면 그 세션의 **모든 이벤트**(앞서 본 입학안내 조회·투어 이용 포함)가 빠집니다. 링크 클릭 이후만 빠지는 것이 아닙니다.
3. 탭 설정
   - **세그먼트 비교:** '전체 세션(비교용)'과 '수업 사이트 이동 세션 제외'를 넣습니다.
   - **측정항목:** 세션수, 총 사용자 수(또는 활성 사용자), 조회수, 이벤트 수
   - **측정기준:** 날짜, 이벤트 이름(투어 이용은 `tour_floor_view`·`tour_room_open` 등), 페이지 위치
4. 읽는 법: '수업 사이트 이동 세션 제외' 열의 사용자 수는 **남은 세션만으로 GA가 다시 중복 제거해 센 값**입니다. 전체 사용자 수에서 수업 사용자 수를 빼서 계산하지 마세요 (같은 사람이 수업 세션과 다른 날 개인 방문을 모두 가진 경우 빼기로는 틀립니다).
5. 배포 직후 확인은 **보고서 → 실시간** 또는 관리 → DebugView에서 `class_route_complete`가 들어오는지 봅니다. 탐색에는 보통 하루 정도 뒤에 반영됩니다.

> GA4 화면 문구는 언어·버전에 따라 조금 다를 수 있습니다. '제외할 그룹 추가'에서 *세션*을 제외하는 선택지를 고르면 됩니다.

### 기본 보고서는?

보고서 탭의 비교(Comparisons)는 측정기준 값으로만 거를 수 있고, '이 이벤트가 있었던 세션 전체 빼기'는 할 수 없습니다. 기본 보고서와 홈 화면 숫자는 계속 **전체 집계**입니다.

## 3. 과거 기록

- `class_route_complete`는 **배포한 날부터** 생깁니다. 그 전(2026-10-27 공개수업 포함)의 수업 방문은 표시가 없어 세그먼트로 빠지지 않습니다.
- 수업 시간대·학교 위치·경영실습실 조회 수 등으로 **추정해서 빼거나 보정하지 않습니다.** 필요하면 '이 날짜 이전에는 수업 방문이 섞여 있을 수 있음'이라고 주석으로만 남깁니다.

## 4. Windsor AI

- 확인한 것: Windsor AI의 GA4 연결은 GA4 데이터를 측정기준·측정항목 단위로 가져오고, 필드로 거르는 방식입니다. GA4 Data API(`runReport`)에는 탐색의 **세그먼트 기능이 없고**, 측정기준 필터로 `이벤트 이름 ≠ class_route_complete`를 걸면 **그 이벤트 한 줄만** 빠질 뿐 같은 세션의 조회·투어 이용은 그대로 남습니다.
- 확인하지 못한 것: Windsor AI 문서에서 세션 세그먼트(이벤트가 있는 세션 전체 제외) 기능은 찾지 못했습니다. 작업 환경에서 windsor.ai 문서 사이트에 접속할 수 없어 필드 목록을 직접 확인하지 못했으니, 최종 확인은 Windsor 지원팀에 문의하세요.
- 따라서 **Windsor AI만으로는 같은 '수업 사이트 이동 세션 제외' 집계를 만들 수 없다고 보고**, 아래 방법 중 하나를 쓰세요.
  1. **GA4 탐색 결과 내보내기:** 2번 탐색 표를 CSV·Google 스프레드시트로 내보내 Windsor AI 보고서 옆에 붙입니다 (수동, 정확함).
  2. **BigQuery 내보내기 + SQL (자동, 정확함):** 관리 → 제품 링크 → BigQuery 링크(일별 내보내기). 무료 샌드박스로 시작할 수 있습니다. **연결한 날부터만** 쌓이고 과거는 채워지지 않습니다. 아래 쿼리 결과를 Looker Studio·스프레드시트(또는 Windsor AI가 BigQuery를 원본으로 지원하면 그쪽)에 연결합니다.
- 하지 말 것: Windsor AI의 전체 사용자 수에서 `class_route_complete` 수나 수업 사용자 수를 빼는 방식 (세션·사용자 중복 때문에 틀립니다).

### BigQuery 쿼리 예시

`프로젝트.analytics_속성번호`는 BigQuery 링크 후 생긴 데이터 세트 이름으로 바꾸세요.

```sql
-- 세션 = 사용자(user_pseudo_id) + GA 세션 번호(ga_session_id)
WITH ev AS (
  SELECT
    user_pseudo_id,
    (SELECT value.int_value FROM UNNEST(event_params) WHERE key = 'ga_session_id') AS session_id,
    event_name
  FROM `프로젝트.analytics_속성번호.events_*`
  WHERE _TABLE_SUFFIX BETWEEN '20261028' AND FORMAT_DATE('%Y%m%d', CURRENT_DATE('Asia/Seoul'))
),
s AS (
  SELECT
    user_pseudo_id, session_id,
    LOGICAL_OR(event_name = 'class_route_complete') AS class_route,
    COUNTIF(event_name = 'page_view') AS page_views,
    COUNTIF(event_name = 'tour_room_open') AS tour_room_opens
  FROM ev
  WHERE session_id IS NOT NULL
  GROUP BY user_pseudo_id, session_id
)
SELECT '전체 집계' AS 구분,
       COUNT(*) AS 세션수,
       COUNT(DISTINCT user_pseudo_id) AS 방문자수,
       SUM(page_views) AS 조회수,
       SUM(tour_room_opens) AS 투어_공간열기
FROM s
UNION ALL
SELECT '수업 사이트 이동 세션 제외',
       COUNTIF(NOT class_route),
       COUNT(DISTINCT IF(NOT class_route, user_pseudo_id, NULL)),   -- 남은 세션 기준으로 다시 중복 제거
       SUM(IF(class_route, 0, page_views)),
       SUM(IF(class_route, 0, tour_room_opens))
FROM s;
```

BigQuery는 사용자를 정확히 세고 GA4 화면은 근사치(HyperLogLog)로 세므로 두 숫자가 조금 다를 수 있습니다.
